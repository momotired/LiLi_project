## 设备管理核心功能后端接口对接文档

面向页面：`pages/device/add.vue`、`pages/device/edit.vue`、`pages/device/list.vue`、`pages/device/detail.vue`

### 一、基础信息

- **Base URL**: `http://localhost:8080/api/v1`
- **认证方式**: 在请求头加入 `Authorization: Bearer <access_token>`（所有设备、分类、模板接口均需登录态）
- **统一响应结构**（后端Beego封装，见 `pkg/utils/response.go`）：

```json
{
  "code": 200,
  "message": "success",
  "data": { /* 业务数据 */ },
  "timestamp": 1710000000
}
```

- **成功判断**: `code === 200`；其他为失败，参考 `message` 提示

### 二、前端表单字段与后端字段映射

当前前端“添加/编辑设备”字段（见 `add.vue` / `edit.vue`）：

| 前端字段 | 示例 | 后端字段 | 是否必填 | 说明 |
| --- | --- | --- | --- | --- |
| name | iPhone 15 | name | 是 | 设备名称 |
| category | 手机 | category_id | 是 | 需先调用“分类列表”拿到 `id`，用 `id` 提交 |
| brand | Apple | brand | 是 | 品牌 |
| model | A3106 | model | 是 | 型号（后端校验为必填） |
| price | 6999 | purchase_price | 是 | 数值型，单位元（小数可用）|
| purchaseDate | 2024-01-02 | purchase_date | 是 | YYYY-MM-DD |
| channel | 官网 | specifications.channel | 否 | 前端字段后端无直连，建议放入 `specifications` 扩展 |
| status | active/idle/repair/broken | 初始为 active；如需“已损坏”用状态接口 | 否 | 创建时默认 `active`；“已损坏”需另调状态更新接口；其它可放 `specifications.usage_status` |
| description | 文本 | notes | 否 | 备注/描述 |
| image | 临时路径 | 通过图片上传接口处理 | 否 | 先创建设备，再调用上传接口保存图片 |

后端还支持的可选字段（前端暂未直接提供）：`serial_number`、`color`、`storage`、`memory`、`processor`、`screen_size`、`warranty_date (YYYY-MM-DD)`、`condition (new/good/fair/poor)`、`images[]`、`specifications{...}`。

注意：创建设备请求还需要 `template_id`（设备模板ID，必填），需通过“模板列表”接口获取或由后端提供默认模板ID。

### 三、接口清单（设备管理）

下述路径均已在后端注册（见 `internal/device/router/router.go`），均在 `/api/v1` 命名空间下，并走 JWT 中间件。

#### 1. 获取分类列表（供选择 category_id）
- GET `/categories/system`（系统分类）
- GET `/categories/custom`（用户自定义分类）
- 也可用 GET `/categories` 并配 `type=system|custom|all`（见类型定义 `GetCategoriesListRequest`）

响应（简化）：
```json
{
  "code": 200,
  "data": { "categories": [ { "id": 1, "name": "手机" }, { "id": 2, "name": "电脑" } ] }
}
```

#### 2. 获取模板列表（供选择 template_id）
- GET `/device-templates` 支持参数：`category_id`、`active`、`page`、`limit`

示例：`/device-templates?category_id=1&active=true&page=1&limit=20`

响应（简化）：
```json
{
  "code": 200,
  "data": { "templates": [ { "id": 101, "name": "手机基础模板" } ] }
}
```

#### 3. 创建设备
- POST `/devices`

请求体：
```json
{
  "template_id": 101,
  "category_id": 1,
  "name": "iPhone 15",
  "brand": "Apple",
  "model": "A3106",
  "purchase_price": 6999,
  "purchase_date": "2024-01-02",
  "notes": "官网购买，第一台",
  "specifications": {
    "channel": "官网",
    "usage_status": "active"
  }
}
```

响应（简化，`data` 为设备对象，含 `id` 等）：
```json
{ "code": 200, "data": { "id": 123, "name": "iPhone 15", "purchase_price": 6999, "created_at": "..." } }
```

校验规则（服务端）：`template_id`、`category_id`、`name`、`brand`、`model`、`purchase_price`、`purchase_date` 必填；`purchase_date` 格式 YYYY-MM-DD。

#### 4. 上传设备图片
- POST `/devices/{deviceId}/images`（`multipart/form-data`）
- 表单字段：
  - `image`（文件，必填，支持 JPEG/PNG/GIF，≤5MB）
  - `image_type`（可选：`normal`/`cover`，默认 `normal`）
  - `sort_order`（可选，数字）

响应：
```json
{ "code": 200, "data": { "image_id": 1, "image_url": "/uploads/devices/..." } }
```

注：前端需使用 `uni.uploadFile` 调用（而非 `uni.request`）。

#### 5. 获取设备详情
- GET `/devices/{deviceId}`

响应：`data` 为设备实体，包含：`id`、`name`、`brand`、`model`、`purchase_price`、`current_value`、`purchase_date`、`status`、`notes`、`images[]` 等。

#### 6. 更新设备
- PUT `/devices/{deviceId}`

请求体（任意可变更字段）：
```json
{ "name": "新名称", "purchase_price": 6999, "purchase_date": "2024-01-10", "notes": "...", "specifications": {"channel": "官网"} }
```

#### 7. 删除设备
- DELETE `/devices/{deviceId}`（软删除）

#### 8. 更新设备状态（例如“已损坏”、“已出售”）
- PATCH `/devices/{deviceId}/status`

请求体示例：
```json
{ "status": "broken", "notes": "摔坏" }
```

出售示例：
```json
{ "status": "sold", "sale_price": 3200, "sale_date": "2025-02-01", "notes": "闲鱼出售" }
```

合法状态：`active`/`sold`/`broken`/`lost`。

#### 9. 获取设备列表（列表页、搜索）
- GET `/devices`
- 查询参数：`page`、`limit`、`category_id`、`status`、`sort`（`created_at`/`purchase_price`/`current_value`/`purchase_date`）、`order`（`asc`/`desc`）、`search`

响应：
```json
{ "code": 200, "data": { "devices": [/* Device[] */], "total": 10, "page": 1, "limit": 10, "total_pages": 1 } }
```

#### 10. 获取设备估值（详情页“价值信息”）
- GET `/devices/{deviceId}/valuation`

响应（简化）：
```json
{
  "code": 200,
  "data": {
    "device_id": 123,
    "purchase_price": 6999,
    "current_value": 5600,
    "depreciation": 1399,
    "depreciation_rate": 20.0,
    "holding_days": 320,
    "daily_depreciation": 4.37
  }
}
```

### 四、最小对接流程（前端建议）

1) 调用分类接口获取分类列表，用户选择得到 `category_id`
2) 调用模板接口获取该分类默认/热门模板，得到 `template_id`
3) 组装创建设备请求体（将 `channel` 放入 `specifications.channel`；`description` 放入 `notes`；`status` 初期默认为 `active`）
4) POST `/devices` 创建成功拿到 `device.id`
5) 如选择了图片，使用 `uni.uploadFile` 调用 `/devices/{id}/images` 逐张上传
6) 跳转详情页：GET `/devices/{id}`（可选再 GET `/devices/{id}/valuation`）

### 五、前端改动建议（与当前代码保持一致）

- `src/utils/api.js` 中 `API_ENDPOINTS` 建议加上统一前缀 `/api/v1`：
```js
// 设备相关
DEVICES: '/api/v1/devices',
DEVICE_DETAIL: '/api/v1/devices/{id}',
DEVICE_VALUATION: '/api/v1/devices/{id}/valuation',
DEVICE_IMAGES: '/api/v1/devices/{id}/images',
// 分类/模板
CATEGORIES: '/api/v1/categories',
SYSTEM_CATEGORIES: '/api/v1/categories/system',
CUSTOM_CATEGORIES: '/api/v1/categories/custom',
TEMPLATES: '/api/v1/device-templates'
```

- 图片上传需使用 `uni.uploadFile`（携带 `Authorization` 头）：
```js
uni.uploadFile({
  url: API_CONFIG.baseURL + API_ENDPOINTS.DEVICE_IMAGES.replace('{id}', deviceId),
  filePath: localPath,
  name: 'image',
  formData: { image_type: 'cover' },
  header: { Authorization: `Bearer ${TokenManager.getAccessToken()}` },
  success: () => { /* 刷新图片列表 */ }
})
```

### 六、错误码与处理

- 通用错误码见 `pkg/utils/response.go`：`400 参数错误`、`401 认证失败`、`404 资源不存在`、`500 服务器错误`、`2008 数据库错误` 等。
- 前端统一处理：当响应 `code !== 200` 时，使用 `uni.showToast({ title: message || '请求失败', icon: 'none' })` 提示；遇到 `401` 时清理登录态并跳转登录。

### 七、与当前前端字段差异说明

- 前端的 `status`（正常/闲置/维修/已损坏）与后端 `status`（active/sold/broken/lost）并不完全一致：
  - 创建时建议固定为 `active`；
  - “已损坏”再调用状态更新设置为 `broken`；
  - “闲置/维修”可暂存于 `specifications.usage_status`，后续如需后端支持可扩展。
- `channel` 无直连字段，建议放 `specifications.channel`；后续可按需在后端增加字段。
- `template_id` 为后端必填，请确保通过模板接口获取或由后端提供默认模板。
